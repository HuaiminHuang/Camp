# 车载助手 Agent 技术报告与使用文档

## 1. 简介

本文档旨在为车载助手 Agent 提供一份全面的技术报告和使用指南。该 Agent 是一个基于大型语言模型（LLM）的任务型对话系统，具备强大的意图识别（NLU）、多能力平台（MCP）和对话管理（DM）等模块。本文档将详细介绍项目的架构、各模块的功能、以及如何进行二次开发和维护，旨在帮助新成员快速上手。

### 1.1. 项目目标

该项目旨在打造一个功能强大、可扩展性强的车载语音助手。它不仅能够理解用户的自然语言指令，还能完成各种车载场景下的任务，例如：

*   **媒体播放:** 播放音乐、电台、新闻等。
*   **车辆控制:** 控制空调、车窗、灯光等。
*   **导航与地图:** 查询天气、地点、规划路线等。
*   **闲聊:** 进行开放域的对话。

### 1.2. 技术栈

*   **核心语言模型:** 豆包（Doubao）等支持 Function Calling 的大模型
*   **Web 框架:** FastAPI
*   **核心库:**
    *   `requests`: 用于 API 请求
    *   `redis`: 用于缓存和会话管理
    *   `qqmusic_api`: QQ 音乐 API
    *   `sinan`: 时间表达式解析
*   **架构:** 模块化、面向服务的架构

## 2. 系统架构

本车载助手 Agent 采用了先进的模块化和面向服务的架构，将不同的功能解耦到独立的模块中，从而提高了系统的可维护性、可扩展性和灵活性。

### 2.1. 架构图

```
+-----------------+      +-----------------------+      +----------------------+
|      User       |----->|     Client Module     |----->|  Function Call Module|
+-----------------+      +-----------------------+      +----------------------+
                           |           ^                       |
                           |           |                       |
                           v           |                       v
+-----------------+      +-----------------------+      +----------------------+
| External Services|----->|      MCP Core         |<-----|      DM Module       |
| (AMAP, QQ Music)|      |   (Capability Servers)|      | (Dialogue Management)|
+-----------------+      +-----------------------+      +----------------------+
```

### 2.2. 数据流

1.  **用户输入:** 用户通过语音或文本输入指令。
2.  **客户端模块 (`client`):**
    *   接收用户输入，并进行初步处理。
    *   **仲裁 (`arbitration.py`):** 判断用户意图的类型（任务、闲聊、FAQ）。
    *   **改写与关联 (`rewrite.py`, `correlation.py`):** 在多轮对话中，对用户输入进行改写和关联，使其更清晰、完整。
    *   将处理后的请求发送到 `function_call` 模块。
3.  **Function Call 模块 (`function_call`):**
    *   **意图召回:** 通过一个轻量级的模型快速召回一批候选意图。
    *   **LLM Function Calling:** 使用大模型（豆包）的 Function Calling 能力，从候选意图和工具中精确地识别出用户的意图和槽位（参数）。
    *   **对话管理 (`dm`):** 根据识别出的意图，通过 `DMFactory` 将任务分发给相应的 DM 处理器（如 `weather.py`, `music.py`, `maps.py`）。
4.  **对话管理模块 (`dm`):**
    *   接收 NLU 结果，并调用 `mcp_core` 模块来执行具体的功能。
5.  **多能力平台 (`mcp_core`):**
    *   **MCP 客户端 (`mcp_client.py`):** 作为一个统一的客户端，连接到不同的能力服务器。
    *   **能力服务器 (`amp_server.py`, `music_server.py`):** 封装了对外部服务（如高德地图、QQ 音乐）的 API 调用，并将其作为工具提供给 MCP 客户端。
6.  **外部服务:** 高德地图、QQ 音乐等第三方服务。
7.  **自然语言生成 (`nlg.py`):**
    *   `dm` 模块在获取到工具执行结果后，会调用 `client` 模块中的 `nlg.py`。
    *   `nlg.py` 使用大模型将结构化的工具返回结果转换成自然、流畅的语言。
8.  **响应用户:** `client` 模块最终将生成的自然语言响应返回给用户。

## 3. 模块详解

### 3.1. `client` 模块

`client` 模块是 Agent 的前端，负责与用户直接交互，并对用户的输入进行预处理。

*   **`nlu.py` (自然语言理解):** 封装了对 `function_call` 模块的请求，是获取 NLU 结果的入口。
*   **`nlg.py` (自然语言生成):** 调用大模型，将工具返回的结构化数据（如 JSON）转换成用户友好的自然语言。
*   **`arbitration.py` (仲裁):** 在对话的开始阶段，通过 LLM 判断用户的宏观意图，决定是进入任务型对话流程、闲聊模式还是 FAQ 问答。
*   **`correlation.py` (关联):** 在多轮对话中，判断当前用户的输入是否与上一轮对话相关，用于处理更正、补充等情况。
*   **`rewrite.py` (改写):** 在多轮对话中，结合上下文，对用户的省略、指代等不明确的表达进行改写，形成一个完整、清晰的指令。
*   **`reject.py` (拒识):** 一个安全模块，用于识别和拒绝不合适或超出 Agent 能力范围的请求。
*   **`stream_chat.py` (流式闲聊):** 处理闲聊场景，调用支持流式输出的 LLM，实现更自然的对话体验。

### 3.2. `function_call` 模块 (NLU 部分)

这是 Agent 的大脑，负责核心的 NLU 和对话管理功能。

*   **`function.py`:** 定义了 Agent 所支持的所有工具（Function），遵循 OpenAI 的 Function Calling 格式。这里是 Agent 能力的清单。
*   **`slot_process.py`:** 对 LLM 返回的槽位值进行后处理，例如将 “主驾” 映射为 “MAIN”，将百分比转换为小数等。
*   **`chatnlu_infer.py`:**
    *   以 FastAPI 服务的形式，提供了 NLU 和 DM 的核心入口。
    *   实现了“召回 + 精排”的两阶段 NLU 策略：先通过 `intent_recall` 快速筛选候选意图，然后利用 LLM 的 Function Calling 能力进行精确的意图和槽位识别。
    *   **效率优化：高置信度未知意图跳过**：为了提高效率，如果在意图召回阶段，最高分意图是“未知” (`Unknown`，ID 为 "3") 且其置信度极高（`max_score > 0.98`），系统会直接返回“未知-无”，跳过后续昂贵的大模型 Function Calling 步骤。
    *   在 NLU 完成后，通过 `DMFactory` 将任务分发给相应的 `dm` 模块。
*   **`dm/` (对话管理子目录):**
    *   **`factory.py`:** 一个简单的工厂模式，根据意图名称返回对应的 DM 处理器。
    *   **`maps.py`, `music.py`, `weather.py`:** 针对不同领域（地图、音乐、天气）的具体 DM 逻辑。它们负责调用 `mcp_client` 来执行工具，并触发 `nlg` 生成回复。

### 3.3. `client` 模块 (NLG 和 Chat 模型区分)

在 `client` 模块中，`nlg.py` 和 `stream_chat.py` 扮演着不同的角色，并使用不同的模型和处理流程：

*   **`nlg.py` (自然语言生成 - 任务型):**
    *   **作用:** 专门用于将**任务型**工具（如查询天气、播放音乐）返回的结构化数据（JSON）转换成自然、流畅的文本回复。
    *   **模型:** 使用 `DOUBAO_URL` 配置的通用 LLM (例如 `ep-20251029235823-rpsx4`)。
    *   **流程:** 接收 `query` 和 `tool_response` 作为输入，生成最终的自然语言回复。

*   **`stream_chat.py` (流式闲聊 - 闲聊型):**
    *   **作用:** 专门用于处理**开放域的闲聊**。它直接与一个对话专用模型交互，并以流式方式将回复实时返回给用户。
    *   **模型:** 使用 `DOUBAO_BOT_URL` 配置的对话专用 LLM (例如 `bot-20251030121317-g9rvm`)，该模型可能具备更强的对话连贯性或联网能力。
    *   **流程:** 接收 `query` 作为输入，直接生成并流式输出闲聊回复。

**重要区别:**
*   **模型分离:** 任务型 NLG 和闲聊型 Chat 使用不同的 LLM 模型，以适应各自的优化目标。
*   **流程分离:** 任务型回复会经过 `nlg.py` 进行格式化和语言生成，而闲聊型回复则由 `stream_chat.py` 直接生成并流式输出，**不会再经过 `nlg.py` 进行二次处理**。这种设计确保了闲聊的实时性和互动性。

### 3.3. `mcp_core` 模块 (多能力平台)

`mcp_core` 模块体现了“平台化”的设计思想，将工具的实现与对话逻辑解耦。

*   **`mcp_client.py`:** MCP 的客户端，负责与各个能力服务器进行通信，调用其提供的工具。
*   **`amp_server.py`:** 高德地图能力服务器。它封装了高德地图的各种 API（天气、地理编码、路线规划、POI 搜索等），并将其注册为 MCP 工具。
*   **`music_server.py`:** QQ 音乐能力服务器。它封装了 `qqmusic_api`，提供了音乐搜索的工具。

这种架构的优势在于：

*   **模块化:** 每个能力服务器都是独立的，可以独立开发、测试和部署。
*   **可扩展性:** 增加新的能力（例如，集成一个新的 API）只需要创建一个新的能力服务器，而无需修改核心对话逻辑。
*   **灵活性:** 可以根据需要启动或停止不同的能力服务器。

## 4. 使用与维护

### 4.1. 环境配置

1.  **安装依赖:**
    ```bash
    pip install -r requirements.txt
    ```
2.  **配置环境变量:**
    在项目根目录下创建 `.env` 文件，并填入以下内容：
    ```
    API_KEY="your_doubao_api_key"
    BASE_URL="doubao_base_url"
    BOT_URL="doubao_bot_url"
    AMAP_MAPS_API_KEY="your_amap_api_key"
    
    NLU_URL="http://localhost:8009/chatnlu-server/v1"
    REJECT_URL="your_reject_service_url"
    INTENT_URL="your_intent_recall_service_url"
    ```

### 4.2. 启动服务

1.  **后台启动各项服务**
    ```bash
    source config/config.ini
    bash server.sh
    ```
2.  **日志检查**
    ```bash
    tail -f log/<对应服务>
    ```

### 4.3. 如何扩展 Agent

#### 4.3.1. 增加新的意图和槽位

1.  **`function_call/function.py`:** 在 `tools1` 列表中，按照 OpenAI Function Calling 的格式添加新的 function 定义。
2.  **`config/class.txt`:** 添加新的 `id:name:func` 映射。
3.  **`config/slot_intent.json`:** 如果有新的槽位，添加槽位名的映射。
4.  **训练意图召回模型:** (如果 `intent_recall` 服务是自己训练的) 需要用新的意图数据重新训练模型。

#### 4.3.2. 增加新的领域 (Domain)

1.  **创建新的能力服务器:**
    *   在 `mcp_core` 目录下，创建一个新的 `xxx_server.py`。
    *   使用 `@mcp.tool()` 装饰器来定义和封装新的工具。
2.  **创建新的 DM 处理器:**
    *   在 `function_call/dm` 目录下，创建一个新的 `xxx.py`。
    *   实现 `process(func_name, query, slots)` 函数，在该函数中调用 `mcp_client` 来执行新工具。
3.  **注册新的 DM 处理器:**
    *   在 `function_call/dm/factory.py` 的 `PARSER_MAPPING` 中，添加新的领域名称和处理器的映射。

## 5. 总结

车载助手 Agent 项目采用了一套现代化、高内聚、低耦合的架构。通过将 NLU、DM、MCP 等核心功能模块化，项目不仅实现了强大的功能，还保证了良好的可扩展性和可维护性。希望本篇技术报告和使用文档能为后续的开发和维护工作提供清晰的指引。
