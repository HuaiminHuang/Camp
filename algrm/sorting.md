# 1. **选择排序（Selection Sort）** 

---

### 🌱 一、算法思路概述

选择排序的核心思想是：

> 每一轮从未排序的部分中 **选出最小的元素**，放到当前未排序区间的 **最前面**。

也就是说：

* 排序区间逐步扩大；
* 未排序区间逐步缩小；
* 每次确定一个“最小值”的最终位置。

---

### 🧩 二、代码逻辑解析

```python
def selection_sort(nums: list[int]):
    """选择排序"""
    n = len(nums)
    # 外层循环：控制未排序区间的起始位置 i
    for i in range(n - 1):
        k = i  # 假设当前 i 是最小值的索引
        # 内层循环：从 i+1 到末尾寻找更小的元素
        for j in range(i + 1, n):
            if nums[j] < nums[k]:
                k = j  # 记录更小元素的索引
        # 找到最小值后，交换到前面（位置 i）
        nums[i], nums[k] = nums[k], nums[i]
```

---

### 📘 三、运行示例

假设我们要排序的列表为：

```python
nums = [5, 3, 6, 2, 4]
```

#### 第 1 轮（i = 0）：

* 未排序区间 `[5, 3, 6, 2, 4]`
* 找最小值 → 是 `2`（索引 `3`）
* 交换 `nums[0]` 和 `nums[3]`
* 得到 `[2, 3, 6, 5, 4]`

#### 第 2 轮（i = 1）：

* 未排序区间 `[3, 6, 5, 4]`
* 最小值是 `3`（索引 `1`）
* 不需要交换
* 仍为 `[2, 3, 6, 5, 4]`

#### 第 3 轮（i = 2）：

* 未排序区间 `[6, 5, 4]`
* 最小值是 `4`（索引 `4`）
* 交换 `nums[2]` 和 `nums[4]`
* 得到 `[2, 3, 4, 5, 6]`

#### 第 4 轮（i = 3）：

* 未排序区间 `[5, 6]`
* 最小值是 `5`
* 不需要交换

排序完成 ✅
最终结果：

```python
[2, 3, 4, 5, 6]
```

---

非常好的问题 👍
——“为什么**选择排序**是不稳定的？”这其实是很多初学者容易忽略的一个关键细节。

我们来**深入剖析稳定性破坏的机制**。

---

## 🧠 一、什么叫排序的“稳定性”？

排序算法的**稳定性**指的是：

> **如果两个元素的值相等，排序后它们的相对顺序保持不变**。

---

## 🧩 二、选择排序打乱稳定性的原因

回顾核心代码：

```python
nums[i], nums[k] = nums[k], nums[i]
```

选择排序在每一轮中：

* **找到未排序区间的最小值索引 `k`**
* **然后直接和位置 `i` 的元素交换**

⚠️ 问题就在这个“交换”动作。

---

### 举个具体例子 👇

```python
nums = [5₁, 3, 5₂]
```

（这里 5₁ 和 5₂ 表示两个相等但不同“身份”的元素。）

#### 第 1 轮：

* 未排序区间 `[5₁, 3, 5₂]`
* 最小值是 `3`（索引 1）
* 交换 `nums[0]` 和 `nums[1]`

得到：

```python
[3, 5₁, 5₂]
```

目前还没问题。

#### 第 2 轮：

* 未排序区间 `[5₁, 5₂]`
* 最小值是 `5₁`（索引 1）
* 交换 `nums[1]` 和 `nums[1]` → 无变化

稳定。

---

再看一个更能体现问题的例子：

```python
nums = [5₁, 5₂, 3]
```

#### 第 1 轮：

* 未排序区间 `[5₁, 5₂, 3]`
* 最小值 `3`（索引 2）
* 交换 `nums[0]` 和 `nums[2]`

得到：

```python
[3, 5₂, 5₁]
```

看到了吗？
原来 5₁ 在 5₂ 前，但现在被换到 5₂ 的后面了。
相等的元素 **相对顺序被破坏** → **不稳定**

---

## ⚙️ 三、总结成一句话

选择排序之所以不稳定，是因为：

> 它在找到最小元素后会直接与前端元素交换位置，
> 这个交换可能把后面的相同元素提前到前面的相同元素之前。

---

## ✅ 四、稳定改进思路（可选）

如果想让它**稳定**，可以这样改：

* 不做交换；
* 而是**用插入的方式**将最小元素插入到 `i` 位置。

```python
# 稳定版本的选择排序
for i in range(n - 1):
    k = i
    for j in range(i + 1, n):
        if nums[j] < nums[k]:
            k = j
    # 不直接交换，而是把 nums[k] 插入到位置 i
    tmp = nums[k]
    while k > i:
        nums[k] = nums[k - 1]  # 元素整体右移
        k -= 1
    nums[i] = tmp
```

这样相等元素的相对顺序就不会被打乱。
（但代价是多了移动操作，效率变低。）

# 2.冒泡排序

## 一、冒泡排序的核心思想

冒泡排序每一轮（一次“冒泡”）在**未排序区间**里，把**相邻的较大元素向右“冒泡”**，也就是把当前区间的**最大值移动到区间最右端**。
重复这个过程，未排序区间逐渐左移，最终数组有序。

不变式（正确性直觉）：在第 `t` 轮之后，数组最右侧的 `t` 个元素已经是全局最大的 `t` 个元素，且它们处在正确的最终位置。

经典代码：

```python
def bubble_sort(nums: list[int]):
    """冒泡排序"""
    n = len(nums)
    # 外循环：未排序区间为 [0, i]
    for i in range(n - 1, 0, -1):
        # 内循环：将未排序区间 [0, i] 中的最大元素交换至该区间的最右端
        for j in range(i):
            if nums[j] > nums[j + 1]:
                # 交换 nums[j] 与 nums[j + 1]
                nums[j], nums[j + 1] = nums[j + 1], nums[j]
```

---

## 二、逐步示例（便于理解“冒泡”过程）

以 `nums = [4, 2, 7, 3, 1]` 为例：

初始：`[4, 2, 7, 3, 1]`

* 第1轮（i = 4，内循环 j 从 0 到 3）：

  * 比较 4 与 2 → 交换 → `[2, 4, 7, 3, 1]`
  * 比较 4 与 7 → 不交换 → `[2, 4, 7, 3, 1]`
  * 比较 7 与 3 → 交换 → `[2, 4, 3, 7, 1]`
  * 比较 7 与 1 → 交换 → `[2, 4, 3, 1, 7]`
  * 结果：最大 `7` 已放在最右端（最终位置）

* 第2轮（i = 3）：

  * 比较 2-4 → 不换
  * 比较 4-3 → 换 → `[2, 3, 4, 1, 7]`
  * 比较 4-1 → 换 → `[2, 3, 1, 4, 7]`
  * 结果：`4` 放到第 4 位

* 第3轮（i = 2）：

  * 比较 2-3 → 不换
  * 比较 3-1 → 换 → `[2, 1, 3, 4, 7]`

* 第4轮（i = 1）：

  * 比较 2-1 → 换 → `[1, 2, 3, 4, 7]`

排序完成。

---

## 三、复杂度、空间和稳定性

* 时间复杂度：

  * 最坏 / 平均：$O(n^2)$（约为 $\frac{n(n-1)}{2}$ 次比较）
  * 最好（已近乎有序或完全有序）：如果不做优化仍然是 $O(n^2)$；但做标志位优化后可达到 $O(n)$（只需一次扫描发现无交换就退出）
* 交换次数：在最坏情况下（降序）约为 $\frac{n(n-1)}{2}$
* 空间复杂度：$O(1)$（原地排序）
* 稳定性：**稳定**。原因：只交换相邻元素，且只有在前者大于后者时才交换，相等元素不会被越过或以非相邻方式互换，从而保持相同键的相对顺序。

---

## 四、标志位优化

标志位优化的思路很简单：如果某一轮内没有发生任何交换，说明数组已经有序，可以提前终止，避免无意义的后续轮次。

代码：

```python
def bubble_sort_with_flag(nums: list[int]):
    """冒泡排序（标志优化）"""
    n = len(nums)
    # 外循环：未排序区间为 [0, i]
    for i in range(n - 1, 0, -1):
        flag = False  # 初始化标志位
        # 内循环：将未排序区间 [0, i] 中的最大元素交换至该区间的最右端
        for j in range(i):
            if nums[j] > nums[j + 1]:
                # 交换 nums[j] 与 nums[j + 1]
                nums[j], nums[j + 1] = nums[j + 1], nums[j]
                flag = True  # 记录交换元素
        if not flag:
            break  # 此轮“冒泡”未交换任何元素，直接跳出
```

**优点**：

* 对于已经有序或接近有序的数据非常有效：最佳情况时间复杂度降为 (O(n))（一次完整的内循环比较后发现无交换便退出）。
* 简单、开销极小（只额外一个布尔变量）。

**缺点**：

* 对于完全乱序或逆序数组，仍然是 (O(n^2))。

---

## 五、进一步的改进

1. **记录最后一次发生交换的位置（last_swap）**：

   * 思路：每轮记录内循环中最后一次交换的位置 `last_swap`，下一轮未排序区间只需到 `last_swap - 1` 即可，因为 `last_swap` 之后的元素已是有序的。
   * 这种方式比单纯的 `flag` 更能利用部分有序性，从而减少不必要比较。
   * 伪码 / 实现：

```python
def bubble_sort_last_swap(nums: list[int]):
    n = len(nums)
    end = n - 1
    while end > 0:
        last_swap = 0
        for j in range(end):
            if nums[j] > nums[j + 1]:
                nums[j], nums[j + 1] = nums[j + 1], nums[j]
                last_swap = j + 1  # 记录位置（或 j）
        end = last_swap - 1  # 下一轮只需到 last_swap-1
        if last_swap == 0:
            break
```

2. **双向冒泡（Cocktail Shaker / 双端冒泡）**：

   * 在一趟中先从左到右把最大元素送到右端，再从右到左把最小元素送到左端。适合“中心乱，两端有序”的情况，减少总轮数。
   * 代码示例（简化版）：

```python
def cocktail_shaker_sort(nums):
    n = len(nums)
    left, right = 0, n - 1
    while left < right:
        # 从左向右冒泡（放最大）
        for j in range(left, right):
            if nums[j] > nums[j + 1]:
                nums[j], nums[j + 1] = nums[j + 1], nums[j]
        right -= 1
        # 从右向左冒泡（放最小）
        for j in range(right, left, -1):
            if nums[j - 1] > nums[j]:
                nums[j - 1], nums[j] = nums[j], nums[j - 1]
        left += 1
```

---

非常好，这段代码展示了 **插入排序（Insertion Sort）** 的经典实现。
我们来从思想、代码细节、例子、复杂度和稳定性等角度，系统、深入地讲清楚它。

---

## 🧠 一、核心思想：像打扑克牌一样“插牌”

插入排序的核心直觉非常形象：

> 就像你一张一张地拿起扑克牌，每拿到一张，就**把它插入到你手里已经排好序的那一部分中合适的位置**。

也就是说：

* 前半部分 `[0, i-1]` 始终是**有序区间**；
* 当前要插入的元素 `nums[i]` 是**待插入元素**；
* 通过在已排序区间中不断**向左比较并移动元素**，为 `nums[i]` 找到正确位置。

---

## 🧩 二、代码逻辑逐行解释

```python
def insertion_sort(nums: list[int]):
    """插入排序"""
    # 外循环：已排序区间为 [0, i-1]
    for i in range(1, len(nums)):
        base = nums[i]  # 待插入元素
        j = i - 1       # 从已排序区间的末尾开始比较
        # 向左扫描，将比 base 大的元素都往右移一位
        while j >= 0 and nums[j] > base:
            nums[j + 1] = nums[j]  # 元素右移
            j -= 1
        # 找到了 base 的正确位置
        nums[j + 1] = base
```

关键点：

* `base` 是当前需要插入的“牌”；
* `while` 循环不断右移较大的元素，为 `base` 腾出位置；
* 当循环退出时，`j + 1` 就是 `base` 应该插入的位置。

---

## 📘 三、运行示例（完整过程演示）

假设：

```python
nums = [5, 3, 4, 1, 2]
```

### 初始状态：

* 已排序区间 = `[5]`
* 未排序区间 = `[3, 4, 1, 2]`

---

### 第 1 轮（i = 1，base = 3）

* 比较 `5 > 3` → 是，右移
* 数组变为 `[5, 5, 4, 1, 2]`
* j 变为 -1，循环结束
* 插入 base 到位置 `j+1=0`
* 结果 → `[3, 5, 4, 1, 2]`

---

### 第 2 轮（i = 2，base = 4）

* 比较 `5 > 4` → 是，右移 → `[3, 5, 5, 1, 2]`
* 比较 `3 > 4` → 否，停止
* 插入 base 到位置 1 → `[3, 4, 5, 1, 2]`

---

### 第 3 轮（i = 3，base = 1）

* 依次右移：5→4→3
* 最终 `[1, 3, 4, 5, 2]`

---

### 第 4 轮（i = 4，base = 2）

* 右移：5→4→3
* 插入位置在 `j+1=1`
* 结果 `[1, 2, 3, 4, 5]`

✅ 最终排序完成。

## ⚙️ 四、复杂度分析

| 情况        | 比较/移动次数        | 时间复杂度    |
| --------- | -------------- | -------- |
| 最好（数组已升序） | 每次只比较一次        | (O(n))   |
| 最坏（数组降序）  | 每次都右移所有前项      | (O(n^2)) |
| 平均情况      | 一半元素右移         | (O(n^2)) |
| 空间复杂度     | (O(1))（原地排序）   |          |
| 稳定性       | ✅ 稳定（不会打乱相等元素） |          |

# **快速排序（Quick Sort）**

---

### 一、核心思想

快速排序是一种 **分治算法（Divide and Conquer）**。它通过一次划分（partition）把数组分成两部分：

* 左边的数都比「基准数」小；
* 右边的数都比「基准数」大；
* 然后递归地对左右两部分继续排序。

---

### 二、从代码看流程

#### 1. `partition()` 哨兵划分函数

```python
def partition(self, nums, left, right):
    i, j = left, right
    while i < j:
        while i < j and nums[j] >= nums[left]:
            j -= 1
        while i < j and nums[i] <= nums[left]:
            i += 1
        nums[i], nums[j] = nums[j], nums[i]
    nums[i], nums[left] = nums[left], nums[i]
    return i
```

这个函数的目标是：

* 选取最左端元素 `nums[left]` 作为「基准数」；
* 通过两个指针 `i` 和 `j`（哨兵），分别从两边往中间移动；
* 把比基准数小的放到左边，比基准数大的放到右边；
* 当左右哨兵相遇时，把基准数放到中间；
* 返回基准数最终所在的位置。

---

#### 2. `quick_sort()` 主递归函数

```python
def quick_sort(self, nums, left, right):
    if left >= right:
        return
    pivot = self.partition(nums, left, right)
    self.quick_sort(nums, left, pivot - 1)
    self.quick_sort(nums, pivot + 1, right)
```

这个函数：

* 先调用 `partition()` 完成一次划分；
* 再递归地处理基准数左边的子数组和右边的子数组；
* 当子数组长度为 1 时，递归终止。

---

### 三、举个例子

假设输入：

```python
nums = [4, 1, 7, 3, 2, 6, 5]
```

执行：

```python
quick_sort(nums, 0, 6)
```

#### 第一次调用：

* 基准数 = `4`
* 左指针 `i` 从左到右找第一个 > 4 的数（找到 7）
* 右指针 `j` 从右到左找第一个 < 4 的数（找到 2）
* 交换后：`[4, 1, 2, 3, 7, 6, 5]`

继续循环：

* `i` 向右走到 7 处，`j` 向左走到 3 处
* 再交换：`[4, 1, 2, 3, 7, 6, 5]`（其实此时 `i == j`）
* 循环结束，把基准数 4 与 `nums[i]`（3）交换：
  得到：`[3, 1, 2, 4, 7, 6, 5]`
* 此时返回的 pivot = 3（基准数 4 的新索引）

数组被划分为：

* 左子数组 `[3, 1, 2]`
* 右子数组 `[7, 6, 5]`

---

#### 递归左子数组 `[3, 1, 2]`

基准数 = 3 → 划分结果 `[2, 1, 3]` → 继续递归 `[2, 1]` → 排好 `[1, 2]`
得到左侧有序 `[1, 2, 3]`

---

#### 递归右子数组 `[7, 6, 5]`

基准数 = 7 → 划分结果 `[5, 6, 7]`
得到右侧有序 `[5, 6, 7]`

---

### 四、最终结果

合并后整个数组为：

```python
[1, 2, 3, 4, 5, 6, 7]
```

```
quick_sort(0,6) 基准=4
├─ quick_sort(0,2) 基准=3
│  ├─ quick_sort(0,1) 基准=2
│  │  ├─ quick_sort(0,0) → stop
│  │  └─ quick_sort(2,1) → stop
│  └─ quick_sort(3,2) → stop
└─ quick_sort(4,6) 基准=7
   ├─ quick_sort(4,5) 基准=5
   │  ├─ quick_sort(4,3) → stop
   │  └─ quick_sort(5,5) → stop
   └─ quick_sort(7,6) → stop

```

## 基准数优化

---

## 一、背景问题：普通快排的性能隐患

在普通快速排序中，`partition()` 通常直接选择第一个元素 `nums[left]` 作为**基准数 (pivot)**。
这种方法虽然简单，但在某些情况下会导致非常糟糕的性能：

例如：

```python
nums = [1, 2, 3, 4, 5, 6, 7]
```

每次选最左边的元素做基准，划分结果会是：

```
基准=1 → [1] | [2,3,4,5,6,7]
```

再递归 `[2,3,4,5,6,7]`，又选 2 为基准 → [2] | [3,4,5,6,7]
……如此递归。

这就退化成了「每次只划分出一个元素」，递归深度达到 O(n)，
从而时间复杂度退化为 **O(n²)**。

---

## 二、优化思路：三数取中法（Median-of-Three）

为避免这种极端不平衡的划分，改进思路是：

> 不直接拿第一个元素，而是从「左、中、右」三个位置取数，
> 选它们的**中位数（median）**作为基准。

举个例子：

假设数组为：

```
[4, 9, 1, 6, 3, 8, 2]
```

取：

* left = 0 → nums[left] = 4
* mid = 3 → nums[mid] = 6
* right = 6 → nums[right] = 2

三数为 `[4, 6, 2]`
中位数是 **4**（居中值）。

→ 选 4 作为基准。

即便数组是几乎有序的，这样选出的基准仍然比较靠中间，
能让划分结果更平衡。

---

## 三、代码解析

### (1) 三数取中函数

```python
def median_three(self, nums, left, mid, right):
    l, m, r = nums[left], nums[mid], nums[right]
    if (l <= m <= r) or (r <= m <= l):
        return mid  # m 是中位数
    if (m <= l <= r) or (r <= l <= m):
        return left  # l 是中位数
    return right
```

判断逻辑：

* 若 `m` 夹在 `l` 和 `r` 之间，则返回中间索引 `mid`
* 若 `l` 夹在两者之间，则返回 `left`
* 否则中位数就是右端元素，返回 `right`

---

### (2) 在 partition 中使用

```python
def partition(self, nums: list[int], left: int, right: int) -> int:
    """哨兵划分（三数取中值）"""
    # 以 nums[left] 为基准数
    med = self.median_three(nums, left, (left + right) // 2, right)
    # 将中位数交换至数组最左端
    nums[left], nums[med] = nums[med], nums[left]
    # 以 nums[left] 为基准数
    i, j = left, right
    while i < j:
        while i < j and nums[j] >= nums[left]:
            j -= 1  # 从右向左找首个小于基准数的元素
        while i < j and nums[i] <= nums[left]:
            i += 1  # 从左向右找首个大于基准数的元素
        # 元素交换
        nums[i], nums[j] = nums[j], nums[i]
    # 将基准数交换至两子数组的分界线
    nums[i], nums[left] = nums[left], nums[i]
    return i  # 返回基准数的索引
```

这一步把「中位数」交换到最左端（方便复用原哨兵划分逻辑）。
