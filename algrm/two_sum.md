## 两数之和

非常好，这两个函数分别实现了经典算法题 **「Two Sum」**（两数之和）的两种思路：
一个是**暴力解法**，另一个是**哈希表优化解法**。下面我们从思路、时间复杂度、空间复杂度和执行过程逐点对比分析。

---

### ✅ 一、暴力枚举法（`two_sum_brute_force`）

```python
def two_sum_brute_force(nums: list[int], target: int) -> list[int]:
    for i in range(len(nums) - 1):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return [i, j]
    return []
```

#### 🧠 思路：

* 枚举所有可能的数对 `(i, j)`；
* 检查 `nums[i] + nums[j] == target`；
* 若相等，立即返回这两个下标。

#### 🕒 时间复杂度：

* 外层循环 O(n)
* 内层循环 O(n)
* 总体是 **O(n²)**
  （每个元素都要和后面的所有元素相加一次）

#### 💾 空间复杂度：

* 没有使用额外存储结构，只有常数级变量。
* 空间复杂度是 **O(1)**

#### 📊 特点：

* **优点**：逻辑直观、容易理解；
* **缺点**：当 n 很大时效率极低，属于最原始的解法；
* **使用场景**：用于教学或小数据量场景。

---

### ⚡ 二、哈希表法（`two_sum_hash_table`）

```python
def two_sum_hash_table(nums: list[int], target: int) -> list[int]:
    dic = {}
    for i in range(len(nums)):
        if target - nums[i] in dic:
            return [dic[target - nums[i]], i]
        dic[nums[i]] = i
    return []
```

#### 🧠 思路：

* 用一个字典 `dic` 存储已经遍历过的数字及其下标；
* 对当前数字 `nums[i]`：

  * 计算需要的“补数” `complement = target - nums[i]`；
  * 若补数已在字典中，说明之前有一个数与当前数和为 target；
  * 否则把当前数加入字典中；
* 由于哈希表查找是 **O(1)** 平均时间，因此整体非常快。

#### 🕒 时间复杂度：

* 只需单次遍历列表：O(n)
* 查找/插入字典：O(1)
* **总体时间复杂度：O(n)**

#### 💾 空间复杂度：

* 需要一个哈希表存储已访问的元素；
* 最坏情况下存储 n 个元素；
* **空间复杂度：O(n)**

#### 📊 特点：

* **优点**：大幅提升运行效率，从 O(n²) → O(n)；
* **缺点**：需要额外空间；
* **使用场景**：绝大多数生产/竞赛场景下的首选方法。

---

### 🔍 三、执行过程对比（例）

假设：

```python
nums = [2, 7, 11, 15]
target = 9
```

#### 暴力法过程：

* i=0, j=1 → 2+7=9 ✅ → 返回 [0,1]
* 完成。

#### 哈希法过程：

| i | nums[i] | target - nums[i] | dic状态 | 动作            |
| - | ------- | ---------------- | ----- | ------------- |
| 0 | 2       | 7                | {}    | 加入 dic[2]=0   |
| 1 | 7       | 2                | {2:0} | 找到2 ✅ 返回[0,1] |

→ 同样返回 `[0,1]`，但查找速度更快。

---

### ⚖️ 四、对比总结

| 特性    | 暴力法    | 哈希表法         |
| ----- | ------ | ------------ |
| 时间复杂度 | O(n²)  | O(n)         |
| 空间复杂度 | O(1)   | O(n)         |
| 思路    | 双重循环枚举 | 一次遍历 + 哈希表查找 |
| 优点    | 简单直观   | 高效、实用        |
| 缺点    | 慢、不可扩展 | 占空间          |
| 实际应用  | 小规模或教学 | 大规模主流实现      |
